PROPGRID.DLL

The flat C API underneath everything else: 42 exported functions, one opaque handle per grid, no COM, no classes and no callbacks you have to implement. This is the layer PropGridClass wraps — and the one to bind to from any language that can call __stdcall. Written from src\propgrid.h and src\propgrid.cpp; the line references point at the shipped source.

La API C plana que hay debajo de todo lo demás: 42 funciones exportadas, un handle opaco por rejilla, sin COM, sin clases y sin callbacks que usted tenga que implementar. Es la capa que envuelve PropGridClass — y a la que hay que enlazar desde cualquier lenguaje que sepa llamar __stdcall. Redactada a partir de src\propgrid.h y src\propgrid.cpp; las referencias de línea apuntan al código entregado.

42 exports · __stdcall · ANSI · undecorated names · pinned ordinals · 32-bit

OverviewResumen

One call creates a grid over a parent window and hands back an HPG. Every other call takes that handle back. There is no object, no interface and no inheritance — all the state lives inside the DLL and you reach it through PG_Set… / PG_Get… pairs.

Property in the OO senseWhat the DLL has instead
A class with fieldsAn opaque HPG (a void*) and functions that take it as the first argument.
Public propertiesNamed slots: colours by PGC_ index, fonts by PGF_ index, and a handful of scalar setters. All listed under Per-grid state.
Per-item propertiesRow and category ids (small positive integers) plus setters that take one. See Per-row / per-category.
EventsA poll queue (PG_PollEvent) and/or one optional __stdcall callback.
You probably want the class instead. In Clarion, PropGridClass already wraps every function here and adds the parts the DLL cannot know about — reading the window, writing USE variables, folding lookups, tab categories. See the class guide. Bind to the DLL directly when you are not in Clarion, or when you want the grid without any of the Clarion-specific behaviour.

What one grid is

A child window of the parent you pass in, created with WS_CHILD | WS_VISIBLE | WS_CLIPSIBLINGS | WS_VSCROLL | WS_TABSTOP and pinned to the top of its siblings (Clarion SHEET/TAB controls otherwise paint over it). It draws itself with Direct2D and DirectWrite, owns its own vertical scrollbar and in-place editors, and sends the host nothing except the events you poll for.

Una llamada crea una rejilla sobre una ventana padre y devuelve un HPG. Todas las demás llamadas reciben ese handle de vuelta. No hay objeto, ni interfaz, ni herencia — todo el estado vive dentro de la DLL y usted lo alcanza con pares PG_Set… / PG_Get….

Propiedad en sentido OOLo que tiene la DLL en su lugar

Propiedades públicasRanuras con nombre: colores por índice PGC_, fuentes por índice PGF_, y un puñado de setters escalares. Todo listado en Estado por rejilla.
Propiedades por elementoIds de fila y categoría (enteros positivos pequeños) más setters que reciben uno. Vea Por fila / por categoría.

Probablemente quiera la clase. En Clarion, PropGridClass ya envuelve todas estas funciones y añade lo que la DLL no puede saber — leer la ventana, escribir variables USE, plegar búsquedas, categorías por pestaña. Vea la guía de la clase. Enlace directo a la DLL cuando no esté en Clarion, o cuando quiera la rejilla sin nada del comportamiento específico de Clarion.

Qué es una rejilla

Una ventana hija del padre que usted pasa, creada con WS_CHILD | WS_VISIBLE | WS_CLIPSIBLINGS | WS_VSCROLL | WS_TABSTOP y fijada arriba de sus hermanas (si no, los SHEET/TAB de Clarion la pintan encima). Se dibuja con Direct2D y DirectWrite, tiene su propia barra de desplazamiento vertical y sus editores en el sitio, y no manda nada al host salvo los eventos que usted sondea.

Lifetime & the handleVida y el handle

Four calls bracket everything: initialise the library, create a grid, destroy it, shut the library down. The middle two are the only ones that matter per grid.

PG_Initialize();                                 // reference counted, once per process
HPG pg = PG_Create(hwndParent, x, y, w, h, style);
   // ... build, run, poll ...
PG_Destroy(pg);
PG_Shutdown();
CallBehaviour
PG_Initialize cpp:1602Reference counted. The first call creates the Direct2D and DirectWrite factories, registers the window class and calls InitCommonControlsEx; later calls just bump the count and return 1. Returns 0 only if a factory could not be created. PG_Create calls it for you if you forgot, so it is optional.
PG_Create cpp:1633Returns an HPG, or NULL if the window could not be made. x, y, w, h are pixels in the parent's client space. style is a bitwise OR of PGS_ flags; 0 is legal and gives a bare grid.
PG_Destroy cpp:1683Closes any open editor without committing, destroys the child window and frees every row, category, font and registry. The handle is dead afterwards — do not call anything else with it.
PG_Shutdown cpp:1624Decrements the count; at zero it unregisters the window class and releases the factories. Safe to skip at process exit.

The parent must have a message loop, and you must pump events. The grid raises everything through its own queue; nothing reaches the parent as a WM_COMMAND or WM_NOTIFY. If you never call PG_PollEvent (or register a callback) the grid still draws and still edits — you just never hear about it.

Cuatro llamadas enmarcan todo: inicializar la librería, crear una rejilla, destruirla, cerrar la librería. Las dos del medio son las únicas que importan por rejilla.

PG_Initialize();                                 // con conteo de referencias, una vez por proceso
HPG pg = PG_Create(hwndParent, x, y, w, h, style);
   // ... construir, ejecutar, sondear ...
PG_Destroy(pg);
PG_Shutdown();

PG_Initialize cpp:1602Con conteo de referencias. La primera llamada crea las fábricas de Direct2D y DirectWrite, registra la clase de ventana y llama a InitCommonControlsEx; las siguientes sólo suben el contador y devuelven 1. Devuelve 0 sólo si no se pudo crear una fábrica. PG_Create la llama por usted si se le olvidó, así que es opcional.
PG_Create cpp:1633Devuelve un HPG, o NULL si no se pudo crear la ventana. x, y, w, h van en píxeles del área cliente del padre. style es un OR de banderas PGS_; 0 es válido y da una rejilla pelada.

Binding from a languageEnlazar desde un lenguaje

Clarion

PASCAL for __stdcall, NAME() because the exports are undecorated, and RAW wherever a pointer is passed (a *CSTRING or an out parameter) so Clarion sends the address alone with no length behind it.

  MAP
    MODULE('ClaPropGridDLL')                ! any label EXCEPT 'PROPGRID.DLL'
PG_Create   PROCEDURE(UNSIGNED hwndParent, SIGNED x, SIGNED y, |
                      SIGNED w, SIGNED h, ULONG style),LONG,PASCAL,NAME('PG_Create')
PG_AddCategory PROCEDURE(LONG pg, *CSTRING catName),SIGNED,PASCAL,RAW,NAME('PG_AddCategory')
PG_PollEvent   PROCEDURE(LONG pg, *SIGNED row, *SIGNED evType),SIGNED,PASCAL,RAW,NAME('PG_PollEvent')
    END
  END
  PRAGMA('link(propgrid.lib)')                ! this is what links the import lib
The MODULE() label must not be 'PROPGRID.DLL'. Clarion strips the extension, compares the result with the name of the module being compiled, decides the prototypes are defined there, and every one fails with Missing procedure definition: PG_CREATE((LONG,...). The label is only a grouping name — binding is by NAME() plus propgrid.lib.

The complete, working MAP for all 42 exports is the top of clarion\PropGrid.clw — copy it rather than retyping it.

C and C++

#include "propgrid.h" and link propgrid.lib from the MSVC build (the one in bin\, not the Clarion one in clarion\ — they are different formats).

Anything else

Declare the exports stdcall with ANSI strings. The types map as: HPG = pointer-sized integer, int / long = 32-bit signed, COLORREF = 32-bit unsigned, double = 64-bit IEEE, HWND / HPG = 32-bit handle. Nothing is passed by value that is larger than 8 bytes, and no structs cross the boundary at all.

Clarion

PASCAL por __stdcall, NAME() porque las exportaciones no están decoradas, y RAW allí donde se pasa un puntero (un *CSTRING o un parámetro de salida) para que Clarion mande sólo la dirección, sin la longitud detrás.

  MAP
    MODULE('ClaPropGridDLL')                ! cualquier etiqueta MENOS 'PROPGRID.DLL'

                      SIGNED w, SIGNED h, ULONG style),LONG,PASCAL,NAME('PG_Create')

PG_PollEvent   PROCEDURE(LONG pg, *SIGNED row, *SIGNED evType),SIGNED,PASCAL,RAW,NAME('PG_PollEvent')
    END
  END
  PRAGMA('link(propgrid.lib)')                ! esto es lo que enlaza la lib
La etiqueta de MODULE() no puede ser 'PROPGRID.DLL'. Clarion quita la extensión, compara el resultado con el nombre del módulo que está compilando, decide que los prototipos están definidos ahí, y todos fallan con Missing procedure definition: PG_CREATE((LONG,...). La etiqueta es sólo un nombre de agrupación — el enlace es por NAME() más propgrid.lib.

El MAP completo y funcionando de las 42 exportaciones está al principio de clarion\PropGrid.clw — cópielo en vez de reescribirlo.

C y C++

#include "propgrid.h" y enlace propgrid.lib de la compilación MSVC (la de bin\, no la de Clarion en clarion\ — son formatos distintos).

Cualquier otro

Declare las exportaciones stdcall con cadenas ANSI. Los tipos se corresponden así: HPG = entero del tamaño de un puntero, int / long = entero de 32 bits con signo, COLORREF = 32 bits sin signo, double = IEEE de 64 bits, HWND / HPG = handle de 32 bits. Nada mayor de 8 bytes se pasa por valor, y ninguna estructura cruza la frontera.

Ids are positions, and PG_Clear resets them. Row 3 is the third row added since the last clear. There is no delete-one-row call — rebuild with PG_Clear and add again, and re-read every id you kept.
PG_AddCategory does NOT merge by name. Call it twice with "General" and you get two headers both called General. The merge-by-name behaviour belongs to PropGridClass.AddCategory, not to the DLL — at this level, call PG_FindCategory first if you might already have that header.

Two ways to hear about user activity, and you can use both. Neither one sends the parent a window message.

int PG_PollEvent(HPG pg, int* row, int* evType)

cpp:2122

Returns 1 and fills row / evType while the queue has anything in it, 0 when it is empty. Drain it in a loop — one call takes one event. Drive it from a timer, or from an idle handler.

int row, ev;
while (PG_PollEvent(pg, &row, &ev)) {
    switch (ev) {
    case PGE_CHANGED:  /* the user edited row */      break;
    case PGE_BUTTON:   /* a PGT_BUTTON row was hit */ break;
    case PGE_SELECT:   /* selection moved */          break;
    case PGE_DBLCLICK: /* row double-clicked */      break;
    }
}
void PG_SetCallback(HPG pg, PG_EVENTPROC proc, long userData)

cpp:2132

An immediate __stdcall callback, called as the event happens — on the UI thread, inside the grid's window procedure:

void __stdcall MyEvents(long userData, int row, int evType);
PG_SetCallback(pg, MyEvents, (long)(void*)myState);
The callback fires from inside the grid's own painting and input handling. Do not destroy the grid, open a modal dialog, or run a message loop from it. Set a flag and act after you return. The poll queue has none of these constraints, which is why the Clarion class uses it.
The queue holds 64 events. When it is full the oldest are kept and the newest is dropped from the queue — but the callback still fires for it. In practice 64 is far more than a user can generate between two timer ticks; it only matters if you stop polling entirely.

A complete C hostUn host C completo

Everything above, in one file. This is src\testhost.c in miniature: create a plain Win32 window, put a grid on it, pump the events from a timer.

#define WIN32_LEAN_AND_MEAN
#include <windows.h>
#include "propgrid.h"

static HPG g_pg;
static int g_rName, g_rKind, g_rNote, g_rApply;

static LRESULT CALLBACK WndProc(HWND h, UINT m, WPARAM w, LPARAM l)
{
    switch (m) {
    case WM_SIZE: {                          /* keep the grid on the client area */
        RECT rc; GetClientRect(h, &rc);
        if (g_pg) PG_SetPos(g_pg, 8, 8, rc.right - 16, rc.bottom - 16);
        return 0;
    }
    case WM_TIMER: {                         /* drain the event queue */
        int row, ev; char val[256];
        while (PG_PollEvent(g_pg, &row, &ev)) {
            if (ev == PGE_BUTTON && row == g_rApply) {
                PG_GetValue(g_pg, g_rName, val, sizeof(val));
                MessageBoxA(h, val, "Apply", MB_OK);
            }
        }
        return 0;
    }
    case WM_DESTROY: PostQuitMessage(0); return 0;
    }
    return DefWindowProcW(h, m, w, l);
}

int WINAPI WinMain(HINSTANCE hi, HINSTANCE hp, LPSTR cmd, int show)
{
    WNDCLASSW wc = { 0 };
    wc.lpfnWndProc   = WndProc;
    wc.hInstance     = hi;
    wc.hCursor       = LoadCursorW(NULL, IDC_ARROW);
    wc.hbrBackground = (HBRUSH)(COLOR_BTNFACE + 1);

                      PGS_BORDER | PGS_DESCRIPTION);
    if (!g_pg) return 1;

    /* look */
    PG_SetFont(g_pg, PGF_CATEGORY, "Segoe UI", 9, 1, 0);
    PG_SetSplitter(g_pg, 150);

    /* content */
    int cGen = PG_AddCategory(g_pg, "General");
    g_rName = PG_AddProperty(g_pg, cGen, "Name", PGT_TEXT, "Widget Alpha");
    PG_SetDescription(g_pg, g_rName, "The display name.");

    g_rKind = PG_AddProperty(g_pg, cGen, "Kind", PGT_DROP, "Standard");
    PG_SetChoices(g_pg, g_rKind, "Standard|Advanced|Custom");

    /* a value that wraps, and one row in its own font */
    g_rNote = PG_AddProperty(g_pg, cGen, "Note", PGT_MULTITEXT,
        "A long note that is laid out over as many lines as it needs, "
        "growing the row and pushing everything below it down.");
    PG_SetRowWrap(g_pg, g_rNote, -1);
    PG_SetRowFontFace(g_pg, g_rName, PGF_VALUE, "Georgia", 12, 1, 0);

    int cAct = PG_AddCategory(g_pg, "Actions");
    g_rApply = PG_AddProperty(g_pg, cAct, "Apply", PGT_BUTTON, "Apply now");

    PG_Redraw(g_pg);
    SetTimer(h, 1, 100, NULL);               /* the event pump */

    MSG msg;
    while (GetMessageW(&msg, NULL, 0, 0)) {
        TranslateMessage(&msg);
        DispatchMessageW(&msg);
    }
    PG_Destroy(g_pg);
    PG_Shutdown();
    return 0;
}

#define WIN32_LEAN_AND_MEAN
#include <windows.h>
#include "propgrid.h"

static HPG g_pg;
static int g_rName, g_rKind, g_rNote, g_rApply;

static LRESULT CALLBACK WndProc(HWND h, UINT m, WPARAM w, LPARAM l)
{
    switch (m) {
    case WM_SIZE: {                          /* mantener la rejilla en el área cliente */
        RECT rc; GetClientRect(h, &rc);
        if (g_pg) PG_SetPos(g_pg, 8, 8, rc.right - 16, rc.bottom - 16);
        return 0;
    }
    case WM_TIMER: {                         /* vaciar la cola de eventos */
        int row, ev; char val[256];
        while (PG_PollEvent(g_pg, &row, &ev)) {
            if (ev == PGE_BUTTON && row == g_rApply) {
                PG_GetValue(g_pg, g_rName, val, sizeof(val));
                MessageBoxA(h, val, "Apply", MB_OK);
            }
        }
        return 0;
    }
    case WM_DESTROY: PostQuitMessage(0); return 0;
    }
    return DefWindowProcW(h, m, w, l);
}

int WINAPI WinMain(HINSTANCE hi, HINSTANCE hp, LPSTR cmd, int show)
{
    WNDCLASSW wc = { 0 };
    wc.lpfnWndProc   = WndProc;
    wc.hInstance     = hi;
    wc.hCursor       = LoadCursorW(NULL, IDC_ARROW);
    wc.hbrBackground = (HBRUSH)(COLOR_BTNFACE + 1);
    wc.lpszClassName = L"PGHost";
    RegisterClassW(&wc);

    HWND h = CreateWindowExW(0, L"PGHost", L"PropGrid host",
        WS_OVERLAPPEDWINDOW | WS_VISIBLE, CW_USEDEFAULT, CW_USEDEFAULT,
        460, 560, NULL, NULL, hi, NULL);

    PG_Initialize();
    RECT rc; GetClientRect(h, &rc);
    g_pg = PG_Create(h, 8, 8, rc.right - 16, rc.bottom - 16,
                      PGS_BORDER | PGS_DESCRIPTION);
    if (!g_pg) return 1;

    /* aspecto */
    PG_SetFont(g_pg, PGF_CATEGORY, "Segoe UI", 9, 1, 0);
    PG_SetSplitter(g_pg, 150);

    /* contenido */
    int cGen = PG_AddCategory(g_pg, "General");
    g_rName = PG_AddProperty(g_pg, cGen, "Name", PGT_TEXT, "Widget Alpha");
    PG_SetDescription(g_pg, g_rName, "El nombre visible.");

    g_rKind = PG_AddProperty(g_pg, cGen, "Kind", PGT_DROP, "Standard");
    PG_SetChoices(g_pg, g_rKind, "Standard|Advanced|Custom");

    /* un valor que envuelve, y una fila con su propia fuente */
    g_rNote = PG_AddProperty(g_pg, cGen, "Note", PGT_MULTITEXT,
        "Una nota larga que se reparte en tantas lineas como necesite, "
        "haciendo crecer la fila y empujando hacia abajo lo demas.");
    PG_SetRowWrap(g_pg, g_rNote, -1);
    PG_SetRowFontFace(g_pg, g_rName, PGF_VALUE, "Georgia", 12, 1, 0);

GotchasTrampas

SymptomCause
Entry Point Not Found: PG_AddFont (or any late export)The loaded propgrid.dll is older than the import library. Ship the pair.
Every virtual call crashes at a garbage address (Clarion)The two mode defines _PropGridLinkMode_ / _PropGridDllMode_ have no values, so the DLL() attribute is undefined. They must arrive as project defines.
Missing procedure definition: PG_CREATE(...)The Clarion MODULE() label is 'PROPGRID.DLL'. Use any other name.
The grid appears then vanishes behind other controlsA sibling native control is painting over it. PG_Create pins the grid with HWND_TOP, but a control created later can still land above it — create the grid last, or call SetWindowPos yourself.
Two identical category headersPG_AddCategory appends unconditionally. Call PG_FindCategory first.
Nothing happens when the user editsNothing is polling. The DLL never posts to the parent — call PG_PollEvent from a timer or register a callback.
A slider ignores its rangePG_SetRange was called with hi <= lo; the row falls back to 0–100.
The description pane never showsPGS_DESCRIPTION was not in the PG_Create style, and the style cannot be changed afterwards.
Colours come out swappedPG_SetColor takes 0x00BBGGRR, but a PGT_COLOR row's value is "RRGGBB". They really are opposite orders.
